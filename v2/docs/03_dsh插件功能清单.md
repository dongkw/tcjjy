# dsh 股票研究插件功能清单

日期：2026-10-23，更新：2026-10-26。状态：**行情规则与向量检索后端已实现；以下完整插件功能仍按 04 分段交付。**

2026-10-26 调整：本清单是完整功能目录，开发顺序以 [04 分阶段实现方案](04_分阶段实现方案.md) 为准。不要求 F01–F08 一次做完才运行；先做本机数据与规则，再做向量检索和 Agent 研究。兼容和发布后置，业务数据与检索向量统一存 PostgreSQL + pgvector，不保存业务 JSON 文件。向量检索和长期记忆按 [05 方案](05_向量检索与长期记忆.md)正式实现。下列自动盘的完整能力也按需细化，不作为首次运行门槛。

## 1. 产品范围

在 dsh 中提供一组股票研究工具、专用 preset 与任务指令，让模型能查行情、读公告、补证据、运行策略，最后生成有依据的研究和模拟计划。后续连接自动模拟交易内核，并验证策略与 Agent 的增量价值。

本清单的八项是首版业务功能分组；与“Agent 开发八件事”不同，后者是研发工作的八个方面。当前只列需求，不进入编码。

## 2. 研究阶段的八项功能分组

| 编号 | 功能 | 用户能做什么 | 主要交付与验收 |
| --- | --- | --- | --- |
| F01 | 插件加载、配置与研究模式 | 在 dsh 中启用股票研究，配置数据源、业务服务及任务限制 | TypeScript 原生插件可加载/卸载；提供专用 preset/任务指令；配置和服务异常有明确诊断 |
| F02 | 自选股与模拟持仓上下文 | 选择股票池，查询现金、持仓、成本和可用数量 | 绑定账户、股票池、信息截止时间与数据模式；首版读取只读快照，不产生账户交易 |
| F03 | 行情、日线与技术指标 | 查询或刷新价格、成交量、均线、波动等研究数据 | 每项带来源、事件时间和质量；陈旧、缺失、冲突和接口失败可区分 |
| F04 | 公告、财报与证据检索 | 搜索事项、读取正文、追查财务变化 | 支持检索和分段阅读；返回真实证据 ID、来源、公司、期间、单位、公开可用时间和原文位置 |
| F05 | 规则策略分析与基线 | 运行买入条件、持仓退出和风险规则，查看为何通过或失败 | 规则由程序计算；记录策略版本与输入快照，区分研究策略、硬否决和可执行基线 |
| F06 | 结构化研究与模拟计划 | 得到候选、依据、触发/失效条件及有效期；可返回无有效计划 | 程序核验引用和结构；缺必要信息保持阻塞；仓位与预算受固定 policy 限制 |
| F07 | 风控和成交预演 | 提前看预计数量、仓位、费用、资金占用及拒绝原因 | 程序检查已支持的交易和风险约束；给出允许/拒绝/待补充；预演不创建订单、不成交、不修改现金持仓 |
| F08 | 研究留档、对话展示与演示评测 | 追问依据、查看上次报告/计划，观察补查和失败处理过程 | 证据、快照、规则、计划与预演可关联查询；使用 dsh 工具轨迹；固定任务集覆盖正常、补查、阻塞与恢复 |

### F01：插件加载、配置与研究模式

- 通过外部插件和配置挂载，源码保存在 V2 项目中。
- 为股票研究配置工具集合、任务指令和可用模式，不给研究会话授予无关操作能力。
- 可配置数据源、后端地址、股票池规模、缓存期限、业务超时及请求限制；配置中不固化凭据。
- 显示当前数据模式、后端可用性和兼容版本；错误不伪装成成功。

### F02：自选股与模拟持仓上下文

- 查询自选列表和股票基本身份，区分代码、交易所与证券类型。
- 查询绑定模拟账户的只读快照，标明时间和版本；没有持仓时明确返回空仓。
- 首版可导入或使用明确标注的固定模拟快照，不借用旧影子账户的可执行身份。
- 股票池与账户绑定由用户配置，工具调用不能任意扩展到其他账户或证券范围。

### F03：行情、日线与技术指标

- 提供行情、历史日线和已定义的技术指标，可按缺口刷新；指标由代码计算。
- 缓存、失败重试、限流与数据质量检查在业务层实现，避免每轮重复请求相同数据。
- 区分真实事件时间、交易日、抓取时间和是否延迟，支持研究信息截止时间。
- 日线不足、价格异常、同一事实的来源冲突必须可见；历史模式拒绝未来资料。

### F04：公告、财报与证据检索

- 按公司、日期、事项和关键词查询公告及财报；从索引继续读取相关正文。
- 对长资料分块/分页，保留来源及原文指针，不只返回无出处摘要。
- 财务字段明确累计/单季、币种、单位与报告期，不能用模型猜测补齐。
- 保存原文、版本或哈希；模型可以请求已取得证据，不能通过任意路径或 URL 越界读取。
- 实现正文切块、Embedding 和 pgvector 语义检索；按股票、资料类型及信息截止时间过滤，返回原文及可核查来源。关键词查询仍用于精确定位。

### F05：规则策略分析与基线

- 提供一条输入可获取、可重复运行的明确基线，并保留持仓风险/退出检查能力。
- 输出命中规则、输入值、缺失字段和否决原因，保留策略及参数版本。
- 人工假设型研究与自动执行型策略分别标识；研究评分不能自动视为收益概率。
- 输入快照一致、策略版本一致时，确定性规则结果应一致。

### F06：结构化研究与模拟计划

- 研究结果包含事实、推断、不确定性、缺口、风险、证据与后续观察条件。
- 计划包含标的、方向、触发和失效条件、有效时段、证据及策略/policy/账户版本。
- 目标数量、仓位与费用由程序和 policy 算出，模型不能突破资金或风险上限。
- 只接受有限、可验证的条件模板，不执行自由文本、生成代码或自然语言交易命令。
- 保存计划修订和状态；无满足条件的候选时，可以正常完成研究并返回无计划。

### F07：风控和成交预演

- 预演现金、可卖数量、交易数量、预计成本、集中度和支持范围内的交易约束。
- 区分通过、拒绝、输入不足、规则未支持；规则未支持不能默认放行。
- 结果解释是哪条规则、哪个字段导致阻塞，以及需要补什么资料。
- 首版只返回预演，不能产生订单或修改现金/持仓；F06 的计划也仅为草案，不会自动启用。
- 后续真实模拟执行时重新取价并重检，不能直接把预演当成最终成交许可。

### F08：研究留档、对话展示与演示评测

- 增加长期记忆的保存、召回、修订与失效；保存用户明确偏好、未完成事项和有出处的经验，模型历史观点不冒充事实。
- 保存证据、数据快照、策略结果、研究结论、草案计划和预演；通过稳定 ID 关联。
- 使用 dsh 现有对话和工具轨迹展示；首版可用清晰的通用工具卡片，专用股票卡片后续按需求补充。
- 支持“这条判断依据什么”“与上次相比变化在哪”“上次被什么阻塞”等追问。
- 为正常任务、缺数据补查、来源失败、虚构证据、越界请求、取消和恢复准备评测案例。
- 离线样例和真实模型/真实数据验证分别标记；样例演示结果不计为盈利证据。

## 3. 首版共通要求

| 要求 | 功能表现 |
| --- | --- |
| 参数和输出契约 | 工具名称、说明、单位、返回状态清晰；结构校验之外检查业务语义 |
| 证据与时间 | 引用存在且支持结论；公司/期间匹配；历史资料在当时可用 |
| 任务预算 | 复用 dsh 的循环控制，配置并验证适用的限制；后端独立限制请求与长任务消耗 |
| 超时与取消 | 工具响应取消；后端可能仍在运行时返回真实状态，不能谎称任务已停止 |
| 缺口与失败 | 明确区分无数据、接口失败、陈旧、权限不足和规则拒绝 |
| 权限 | 绑定股票池和账户，外部正文不能改变工具与账户权限 |
| 留档与恢复 | 会话 ID 关联业务 artifact；恢复后查询已保存结果，不重复产生相同业务副作用 |
| 宿主兼容 | 固定受支持 dsh 版本，验证插件注册、卸载、结果展示及日志关联 |

## 4. V0.2：自动虚拟盘功能

| 编号 | 功能 | 要交付的结果 |
| --- | --- | --- |
| F09 | 模拟账户、订单与撮合 | 独立账户初始化；委托、部分成交、撤单、到期、拒绝及费用/滑点；明确市场支持范围 |
| F10 | 事务账本与业务幂等 | 订单、成交、现金、持仓与锁仓一致提交；重试和并发不重复成交；同日快照稳定唯一 |
| F11 | 自动调度与计划执行 | 交易日/时段运行研究和监控；草案通过验证并显式启用后，worker 在 policy 内自动执行有效计划 |
| F12 | 运行控制、恢复与对账 | 暂停开仓、撤销计划/未成交订单、异常熔断、重启恢复和资金持仓对账；重要变化可见 |

自动执行 worker 不依赖聊天页面打开，不要求每个价格事件都调用模型。任务调度可以从 dsh 发起，价格监控和交易事实由业务程序负责。计划版本、账户版本、行情时效与风控都在执行前重检。

通知先通过已有界面或留档呈现；独立推送渠道在选择渠道并明确使用方式后再列入实现，不在本轮配置外部发送。

盈利是待验证目标。报告可得出盈利、亏损、样本不足或尚无证据，不通过挑选区间和隐藏成本改变结论。

## 6. dsh 与插件的分工

| dsh 现有机制 | 本插件需要开发 |
| --- | --- |
| 模型接入、会话、工具循环 | 研究任务指令、业务工具说明和结果完成条件 |
| 通用工具注册、参数校验及策略扩展点 | 业务适配、公司/时间/证据校验、账户和证券范围约束 |
| 对话历史、通用上下文管理与工具事件 | 有限证据上下文、业务报告/计划存储和历史结果查询 |
| 通用交互和过程展示 | 股票业务结果与必要的展示适配、插件任务评测 |

插件复用宿主运行机制，不另建 LangGraph 主循环、模型网关或聊天工作台；后续资金与持仓事实不写在聊天记录里充当账本。

## 7. 首版验收任务

> 在 dsh 股票研究模式中，检查指定自选股和只读模拟持仓；模型发现资料不足后继续调用工具，读到有效证据，运行策略，生成草案和风控预演，最后解释有效结论与未解决缺口。

验收必须同时满足：

1. 工具调用来自真实模型的选择，工具执行返回真实业务结果；固定样例需明确标识。
2. 至少覆盖正常研究、自主补查、证据不足和工具失败；结果可引用和回查。
3. 过期数据、虚构引用和越界账户请求被正确处理。
4. 达到完成条件或预算上限会结束，取消和恢复的业务状态可核实。
5. 首版研究与预演前后，账户现金、持仓、订单和成交事实均不变。

## 8. 当前不纳入首版的内容

真实资金交易、任意代码/SQL 执行、浏览器操作平台、独立聊天 UI、多角色投研团队，以及把 Browser Use/OpenHands 等完整 Agent 循环嵌套进来。需要某项外部能力时，优先封装有限工具或有明确预算和输出的研究任务。

当前已有可运行的行情规则、资料入库、本地向量化与检索后端，尚未创建 dsh 插件包；Agent、长期记忆和模拟交易按后续阶段实现。实际入口与测试结果见 [V2 README](../README.md)。
