## 新电脑准备后端

当前启动脚本面向 Windows PowerShell。已验证环境是 Python **3.12**、CPU PyTorch **2.7.1+cpu**；依赖版本在 `requirements.lock`。安装 Git、Python、Docker Desktop 并启动 Docker 后：

```powershell
git clone https://github.com/dongkw/tcjjy.git
Set-Location .\tcjjy\v2
.\scripts\setup.ps1
.\.venv\Scripts\python.exe -m trader_v2.cli prepare-model
.\scripts\vector-demo.ps1
.\scripts\start.ps1
```

默认 API 是 `http://127.0.0.1:8012/docs`，数据库只绑定本机 `127.0.0.1:55432`。健康接口应显示 stage3/schema4。`vector-demo.ps1` 导入合成资料并测试真实本地向量检索，不会执行交易。

官方 Hugging Face 网络不可用时，可显式使用 `prepare-model --endpoint https://hf-mirror.com`。不会自动切换镜像。BGE 模型固定为 `BAAI/bge-small-zh-v1.5`，修订 `7999e1d3359715c523056ef9478215996d62a620`，维度512。模型文件属于可重新下载的本地缓存。

## 新电脑准备 dsh

插件与本机 dsh **源码构建**的 API 对齐，尚未验证所有已发行的桌面版/CLI版本。当前 dsh 版本 `0.1.5-alpha.1`，源码提交：

```text
5dda764ed3aa172535a7967b06ff95d9cbfe536a
```

准备一份独立的 dsh 源码目录，按该版本仓库说明安装 Node/pnpm 和构建依赖。该版本要求 Node `^22.19.0 || >=24.0.0`，packageManager 为 pnpm `11.7.0`。可在新目录中：

```powershell
git clone https://github.com/deepseek-ai/deepseek-harness.git
Set-Location .\deepseek-harness
git checkout 5dda764ed3aa172535a7967b06ff95d9cbfe536a
pnpm install --frozen-lockfile
pnpm run build
```

在新机器配置自己的 DeepSeek 凭据。项目不包含模型密钥，也不把 Codex/Plus 订阅转换成 API 密钥。默认模型路由为 `deepseek-official/deepseek-v4-flash`；可通过脚本的 `-Provider`、`-Model` 指定该 dsh 实际支持且已配置的路由。

回到本项目 `v2/`，后端保持运行，另开终端执行，路径改成新机器的实际 dsh 目录：

```powershell
.\scripts\dsh.ps1 -DshRoot 'D:\deepseek\deepseek-harness' -DumpConfig
.\scripts\dsh.ps1 -DshRoot 'D:\deepseek\deepseek-harness'
```

Web 默认端口3081。脚本会在 `v2/.runtime/` 生成独立 dsh Home、preset 和 patch，并在插件 `node_modules` 重建本机目录链接；这些内容不提交 Git。默认可读取当前用户 `~/.dsh/.credentials.yaml` 中已有凭据，指定其他文件用 `-CredentialsPath`。不会复制密钥到仓库。也可使用 dsh 支持的环境变量凭据，例如在启动终端配置 `DEEPSEEK_API_KEY`，不要写进代码或文档。

一次性研究任务使用同一受支持的 dsh launcher：

```powershell
.\scripts\dsh.ps1 -DshRoot 'D:\deepseek\deepseek-harness' -Mode Headless -Prompt '只使用 fixture 合成资料研究601138的现金流风险；召回同模式记忆，检索、读原文、按需要补查，保存带引用报告，明确资料缺口和样例性质。'
```

Web 使用每会话的 `trader-research` preset；Headless 使用一次性工具组装。两者只挂载本项目研究工具。启动配置检查通过不代表真实模型调用成功。

## Git 与本机数据的区别

Git 保存代码、SQL迁移、测试、示例配置和设计文档。以下内容被忽略，换电脑后需重新生成或单独安全搬运：`.env`、`.venv`、`.runtime`、插件 `node_modules`、模型缓存、Docker 镜像/数据卷、dsh凭据与会话。

仅拉代码可建立一个新的演示数据库；已有报告、资料和记忆不会随 Git 自动迁移。需要沿用旧业务数据时，先单独导出 PostgreSQL 备份并在新电脑恢复，备份不推到 GitHub；用新机器的环境配置连接恢复后的库。旧电脑数据继续保留。Docker 程序与镜像的本机安装位置不属于项目源码，也不需要逐文件复制。
