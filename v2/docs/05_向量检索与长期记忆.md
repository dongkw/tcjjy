# 向量检索、RAG 与长期记忆实现方案

日期：2026-10-26。状态：资料切块、本地 Embedding 与向量检索已实现并验证；长期记忆和 dsh Agent 接入属于第 3 段。

## 1. 为什么要做

本项目同时用于学习 Agent 开发，所以向量检索是正式交付内容。目标是亲手打通资料切块、Embedding、相似度搜索、元数据过滤、引用、记忆读写及效果评测，而不是只启动一个数据库。

向量库按“意思接近”查资料。例如资料写“应收账款增长较快、回款周期延长”，提问“公司的资金回收有没有风险”时，语义检索可能找到这段内容。找到相关内容后，仍要核对公司、时间和正文，不能把相似度视为结论正确的概率。

## 2. 技术选择

| 部分 | 首个实现 |
| --- | --- |
| 数据库 | PostgreSQL + pgvector，普通业务与向量保存在同一数据库 |
| 向量化 | 本地 `BAAI/bge-small-zh-v1.5`，512 维；固定模型修订版本 |
| Python 调用 | Sentence-Transformers 生成向量，PostgreSQL 驱动执行数据库查询 |
| 首个检索方式 | 按股票/时间/类型限制范围后，按余弦距离排序，返回少量片段 |
| 后续学习练习 | HNSW 索引、关键词与向量混合检索、Reranker 重排；逐项比较效果 |

pgvector 在 PostgreSQL 中提供向量类型、距离查询以及精确和近似检索。选择它是为了用一套数据库覆盖本项目的两类数据，而不是增加独立的向量服务。见 [pgvector 官方说明](https://github.com/pgvector/pgvector)。

Embedding 模型将文字编码为向量，与负责对话、工具选择和分析的模型分工不同。BGE 中文模型的使用、检索指令和分数说明见 [BAAI 模型说明](https://huggingface.co/BAAI/bge-small-zh-v1.5)。已下载固定修订 `7999e1d3359715c523056ef9478215996d62a620`，CPU 本地推理已验证；请求不会自动联网下载模型。

## 3. 数据怎样保存

| 表 | 保存内容 |
| --- | --- |
| `documents` | 原始正文、股票、资料类型、来源、原文地址、公开可用时间、抓取时间、版本/内容哈希 |
| `document_chunks` | 文档 ID、块编号、标题路径、原文起止位置、块正文、`vector(512)`、模型修订和切块版本 |
| `agent_memory`（第 3 段规划） | 用户/账户范围、记忆类型、股票、内容、来源记录、创建/更新/失效时间、状态及向量 |

报告、规则结果、账户、持仓和订单仍是普通业务表。向量检索用于找文本资料；查现金、精确股票代码、订单状态或某日价格时直接查业务字段。

## 4. 一份资料如何变成可检索知识

1. 抓取正文并保存来源、公司与公开可用时间；模型生成的研究报告标记为历史观点。
2. 按标题和自然段切块。第一版以约 320 token 为目标，重叠约 40 token，作为可调起点；用模型 tokenizer 计数，含标题等文本后仍不超过模型输入上限。
3. 用固定模型编码块正文，记录模型和切块版本，向量与原文一起存库。文档不添加查询专用指令。
4. 修改内容后重新生成对应版本的块和向量；没有变化的内容不反复编码。失效或删除的来源不继续参与正常召回，历史研究按当时可用版本查询。

模型换了、维度变了或切块方式改了，要重建对应索引数据，不能混合不同模型的向量做距离比较。

## 5. 一次问题如何使用 RAG

问题 → 同模型生成查询向量 → 限定用户/账户、股票、资料类型和信息截止时间 → 向量排序 → 返回片段原文与来源 → 模型阅读并回答。

第一版可从 Top 5 开始，数量与文本预算可调。使用 BGE 检索指令时，只加到查询文本，遵守模型说明；查询和资料始终用同一模型修订。

返回 `chunk_id`、正文、来源、公司、公开可用时间和检索分数。模型需要更多上下文时继续读取原文。答案引用真实块 ID，程序检查引用是否属于本次取得的材料。

不能把“排名第一”当成存在有效证据；准备无关资料和无答案用例，依据本项目评测决定阈值或拒答规则，不照搬一个固定分数。股票、账号与时间边界由 SQL 条件控制。

先用精确检索作为参照。学习 HNSW 时比较召回和延迟，并检查带过滤条件的查询是否减少返回数量；这些问题不交给对话模型猜测。

## 6. 长期记忆怎样使用

长期记忆是“值得以后再用的信息及其管理规则”，向量检索只是召回方法。

- 保存：用户明确偏好、未完成研究事项、有出处的复盘经验；记录来源、有效期和状态。研究结束可记录待验证观点，不能自动升级成已验证事实。
- 读取：新研究开始先查明确配置和相关有效记忆；复杂追问再调用语义召回。重要固定偏好不只依赖一次向量排名。
- 更新：用户改变偏好、事项已完成或观点被新证据推翻时，修订/失效旧记忆并更新向量。
- 展示：支持查看、纠正和删除记忆，能解释这次用了哪条历史记录。

历史报告可检索全文，不重复把每句报告都复制成记忆。账户与持仓读取当前业务表，外部公告不能通过正文指令改用户偏好或交易配置。

## 7. 接入 Agent 的工具

| 工具 | 作用 |
| --- | --- |
| `search_knowledge` | 搜索公告、资料及历史研究片段，带公司、类型和时间条件 |
| `read_evidence` | 通过片段/文档 ID 继续读取原文 |
| `recall_memory` | 在当前用户/账户范围内召回相关有效记忆 |
| `save_memory` | 保存带来源及类型的记忆；工具检查业务字段 |

这些工具经 dsh 调用本项目的 Python 接口。资料导入、向量化和索引维护由程序完成，不要求模型逐块生成向量。

## 8. 学习验收

1. 同义但措辞不同的问题能找到相关原文；记录预期证据及 Top K 命中情况。
2. 不同公司、不同账户以及截止时间之后的资料不能混进结果。
3. 无有效资料时允许返回空；相似分数不当作事实可信度。
4. 报告引用能追溯正文；旧的模型观点与原始公告能区分。
5. 新会话能召回已存偏好或未完成事项；纠正/失效后不再使用旧记忆。
6. 资料更新、删除和重复导入有可检查结果。

目前已验证资料检索、来源与时间过滤、原文指针、重复导入、更新和删除；长期记忆生命周期与生成式引用验收在第 3 段继续。147 项测试与真实模型的学习用例结果见 [06 验收记录](06_第二阶段验收记录.md)。之后再扩展 HNSW、混合检索与重排，分别记录效果和代价。开发顺序见 [04 分阶段方案](04_分阶段实现方案.md)。
